## 第1阶段的代码内容

Garden：

- `ai_worker.py`：将运行任务计数和领取 CAS 放进同一个数据库事务锁，串行和并发 Worker 都传递全局限额。锁复用现有 SQLite BEGIN IMMEDIATE / PostgreSQL advisory lock。允许过期 running 接管但不额外占新槽。
- `ai_routing.py`：A 的尝试预留计数纳入 B 的 running 任务，避免完全忽略通用任务占用；没有改变 A 的供应商选择策略，也没有将 B 接入动态路由。
- `ai_generic_jobs.py`：相同用户/来源/幂等键仅能重放相同 prompt、params、有序参考图字节；内容变化返回409，正常重放返回原任务。UNIQUE竞争回落同样检查内容。
- `ai_provider_admin.py`：后台保存供应商配置时，保留未完成 Generic 任务引用的历史配置代，防止排队任务丢失供应商快照。
- 测试：API冲突/有序参考图、两表共享槽、六独立Session竞争、三独立OS进程竞争、单线程Worker限额、配置代保留、A的预留计入B；迁移测试改成读取实际迁移头，不再写死旧head。
- `ai/interface.py`：修复渐进输出GC保护函数缺少终态常量导入的问题，保留运行中结果，终态后按原保留策略清理。

- 原生 Node 集成测试改名 `scripts/mock-garden-api.node.mjs`，由 `npm run test:mock` 执行，避免被 Vitest 误收集。
